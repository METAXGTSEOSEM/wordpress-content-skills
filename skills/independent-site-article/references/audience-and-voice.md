# Audience and voice calibration

The same topic can be written for a buyer, an owner, an engineer or an operator.
Those readers need different openings, evidence and next steps. Calibrate the
reader before drafting; do not write a generic training document and call it a
buyer article.

## Reader roles

| Reader | What they need first | Useful evidence | Typical CTA |
| --- | --- | --- | --- |
| Owner / business leader | The decision, commercial risk and what changes if they choose wrong | Total cost, project scope, responsibility, timeline, business impact | Approve a shortlist, request a quote, assign an owner |
| Procurement | A comparable basis, qualification questions and risk controls | Specifications, terms, documentation, delivery, compliance responsibility | RFQ, supplier comparison, document request |
| Engineer / technical reviewer | Constraints, standards, compatibility and verification steps | Datasheets, drawings, standards, test methods, calculations | Technical review, drawing request, clarification |
| Operator / maintenance | What they will use, check or troubleshoot | Controls, access, service, safety limits, escalation | Training, service, support |
| End user / consumer | The outcome, fit, trade-offs and confidence | Use cases, price, delivery, returns, independent reviews | Buy, compare, read the next guide |

If the brief names more than one role, choose the primary reader and define what
the secondary reader needs in a clearly labeled section. Do not alternate
between audiences paragraph by paragraph.

## Opening contract

The first two or three short paragraphs should answer:

1. What decision is this page helping the reader make?
2. Why is that decision difficult or costly if handled badly?
3. What should the reader do next?

Do not open with a definition dump, company history, a long list of standards,
or a generic "if you are..." sentence that could fit any topic. A technical term
belongs in the opening only when it changes the reader's decision.

## Avoid the training-manual tone

- Do not write as if the reader is a student who must learn the whole category
  before making a decision.
- Do not stack regulations, standards and definitions before explaining the
  business decision they affect.
- Put compliance details in a "what to verify" or "responsibility" section after
  the reader understands the commercial context.
- Tie each technical point to a decision, risk, document request or question for
  the supplier.
- Prefer short decision-led paragraphs over a lecture with many headings.
- If a term is useful only for internal training, move it to a glossary or omit it.

Compliance content is not legal advice. State the jurisdiction, the source date
and the limits. Do not tell the reader that one certificate or directive settles
classification for every product.

## Voice inputs

Ask for, or reuse from the project:

- the reader's role and decision authority;
- existing knowledge and reading context;
- a real writing sample or approved tone;
- words the company uses and words it avoids;
- the action the reader should take.

If no voice sample exists, use a plain professional voice. Do not invent
first-person experience, factory visits, customer stories or expert credentials.

## Anti-template fingerprint

Before final review, compare this article with two or three existing pages in the
same cluster and with the recent published articles in
`assets/article-style-ledger.csv` when one is supplied. Record:

| Dimension | This article | Existing page(s) | Difference or reason to keep the same pattern |
| --- | --- | --- | --- |
| Title and meta pattern |  |  |  |
| Opening move | Decision / risk / question / scenario / data / misconception |  |  |
| First three H2 sections |  |  |  |
| Example or evidence type |  |  |  |
| Table, steps, FAQ or visual pattern |  |  |  |
| CTA |  |  |  |
| Signature detail | A concrete scenario, constraint, rule, calculation or evidence set unique to this article |  |  |
| Repeated phrases or sentence rhythm |  |  |  |

The product-swap test is mandatory: if changing the product name and keyword
would leave the article intact, it is a template candidate. If the opening,
early section order, evidence type and CTA all repeat another page, revise before
final review. Reusing a heading pattern is acceptable when the reader's task
genuinely requires it; a complete template fingerprint is not.

## Review gate

- The primary reader is named and visible in the opening.
- The opening addresses a decision, not a syllabus.
- Technical and compliance material appears where it affects a decision.
- The CTA fits the reader's authority and business model.
- The article is not a near-duplicate of a sibling page.
- Recent-article differences and one signature detail are recorded.
- No first-hand experience or credential is invented for voice.
