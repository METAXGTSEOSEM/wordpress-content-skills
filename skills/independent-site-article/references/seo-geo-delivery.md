# SEO, GEO and image delivery

The article is not complete until the page fields and visual plan are usable by
an editor. Field lengths and image counts are practical recommendations, not
ranking rules.

## Required delivery fields

| Field | Requirement |
| --- | --- |
| Focus keyword | One primary keyword with intent, market and source |
| Secondary keywords | Same intent; sourced or marked as hypotheses |
| Supporting entities | Names, standards, materials, roles and related concepts |
| SEO title | Reader-facing title; check the live SERP/plugin preview |
| H1 | One clear page title, consistent with the article |
| URL slug | Short, readable and unique in the cluster |
| Meta description | Specific reason to click; no invented claims |
| Excerpt | Editorial summary for archives and internal previews |
| H2 outline | Reader questions, not keyword buckets |
| Internal links | Verified destinations and descriptive anchors |
| CTA | Matches type, audience authority and business model |
| Schema | Only types that match visible content |
| Image plan | Role, placement, caption, alt text, source and rights |
| Length rationale | Recommended range and why it fits the type and evidence |

## Length and image count

Do not assign a universal word count or "one image every N words."

English articles are measured in words; Chinese articles are measured in
characters. Do not use character count for an English article.

Set a provisional length range after the outline and before Draft v1. Do not set
the range after the draft just to fit the output.

For each article, recommend:

- a content-length range based on the reader's decision, the type's required
  sections, the evidence available and the depth of the current results;
- an image count and placement based on the sections that need explanation,
  proof or comparison;
- what should be a photo, diagram, table or screenshot;
- which images the owner must supply and which are optional.

Record the rationale. If the recommendation is "short," explain what was removed
and why. If it is "long," explain which reader questions require the depth.
Record the actual length and explain material variance from the range. A
documented reason is acceptable; an unexplained mismatch is a review finding.

## GEO structure

Use at least three of these where they genuinely help:

- a direct answer near the top;
- a short key-points list;
- a comparison or specification table;
- numbered steps;
- a visible FAQ;
- a clear definition of entities and terms;
- a "what to verify" or "questions to ask" block.

Keep the answer-first summary consistent with the body. Do not add FAQ or schema
blocks that are not visible or that repeat unsupported claims.

## Image plan

Use `assets/image-plan.csv`. Possible roles:

- hero / context;
- product or service;
- factory, process or team;
- structure, diagram or cutaway;
- detail or close-up;
- application or site scenario;
- comparison or before/after;
- chart or data visual;
- author or expert image.

Each image needs:

- placement;
- purpose;
- short caption;
- alt text that describes the image;
- source and rights;
- status: supplied / licensed / to create / not available.

Do not use an unlicensed manufacturer image, a competitor image, a customer site
photo or a generated image that implies a real facility or product. If a real
factory or product image is unavailable, mark it as missing instead of inventing
one.

## Review gate

- One focus keyword and one primary intent for the URL.
- Title, H1, URL and meta description are unique in the cluster.
- Keyword use is natural; no density target.
- GEO summary matches the body.
- Every image has a purpose, caption, alt text and rights status.
- Length, image count and actual length have a recorded basis and variance note.
- Schema matches visible content and does not duplicate plugin output.
